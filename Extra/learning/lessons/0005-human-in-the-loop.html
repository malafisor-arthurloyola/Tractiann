L5 — Human-in-the-loop: por que pausar é melhor que agir

Seu agente decidiu que precisa reprocessar uma análise ou solicitar um retreinamento. Essas ações alteram o estado da plataforma industrial. E se ele estiver errado?

O problema

Imagine que o agente, vendo dados incompletos (como no ticket TKT-INV-11), decide "reprocessar a análise". Mas o correto seria escalar pra humano — afinal, o ativo é um motor de corrente contínua antigo e o modelo não tem dados suficientes.

Dados que o LLM viu (TKT-INV-11):

  • Baseline: parcial (sem features)
  • RMS: parcial (sem samples)
  • Espectro: inconclusive — sem espectro disponível
  • Análises: nenhuma encontrada

O LLM optou por "recomendar reprocessar" — mas sem espectro e sem análises, isso é perigoso: reprocessar sem dado de entrada pode gerar um insight sem base.

A solução: interrupt()

O LangGraph tem um mecanismo nativo chamado interrupt() que pausa a execução do grafo e aguarda confirmação humana antes de prosseguir.

# Pseudocódigo do nó act com interrupt
def act(state):
    if is_action_of_impact(state):
        result = interrupt({
            "action": state["decision"],
            "justification": state["decision_justification"],
            "asset_id": state["asset_id"],
            "gaps": state["data_gaps"],
        })
        # O grafo SÓ continua quando o humano confirma
        # result = True (confirmado) ou False (cancelado)
        if not result:
            return {"decision": "escalate"}
    # Executa a ação
    execute_action(state)

O ciclo de vida de uma interrupção

  1. Grafo roda normalmente até o nó act.
  2. interrupt() pausa — o estado é salvo (checkpoint).
  3. Interface (Streamlit) mostra a justificativa do agente, os dados coletados, os gaps.
  4. Humano confirma ou cancela.
  5. Grafo retoma de onde parou — como se o humano tivesse respondido naquele ponto.

Quando pausar? A regra

Teste seu entendimento

Pergunta 1
Por que orientar não precisa de pausa, mas reprocessar precisa?
Resposta

Orientar é só explicar — não altera nada na plataforma. Reprocessar manda um job de processamento que pode gastar recursos e gerar um novo insight que o cliente vai ver. Se estiver errado, o cliente confia num diagnóstico inválido.

Pergunta 2
O que acontece com o estado do grafo enquanto o humano confirma?
Resposta

O estado é salvo via checkpoint (pode ser em memória ou em Postgres). Quando o humano confirma, o grafo retoma exatamente de onde parou — como se tivesse um "snapshot" do momento da pausa.
