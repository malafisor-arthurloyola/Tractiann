L10 — Correções nos Grafos, Cache e Fluxo HITL

Essa lição mergulha nas correções mais importantes que fizemos no código do agente: como o grafo rota, como o cache invalida, e como o HITL (Human-in-the-loop) funciona na prática.

1. Roteamento do Grafo (route_after_quality)

Antes da correção, o unavailable pule direto para escalate, pulando o decide. Isso resultava em decision=None.

# ANTES (bug):
if verdict == "unavailable":
    return "escalate"  # ← decide NUNCA roda, decision=None

# DEPOIS (corrigido):
if verdict == "unavailable":
    return "decide"    # ← decide RODA e define decision="escalate"

Agora, todos os verdictos (ok, partial, incomplete, unavailable) passam pelo decide. A decisão é sempre tomada com base nos dados e gaps registrados.

2. O Bug do tools_called Merge

O state tools_called usa Annotated[list, operator.add], o que significa que cada retorna appenda à lista existente.

# ANTES (bug):
def investigate(state):
    tools_called = list(state.get("tools_called") or [])
    for tool in CORE_TOOLS:
        ...
        tools_called.append(tool)
    return {"tools_called": tools_called}  # ← retorna a LISTA INTEIRA
    # operator.add: [5]+[5]+[5] = 15 entries duplicados!

# DEPOIS (corrigido):
def investigate(state):
    new_tools = []
    for tool in CORE_TOOLS:
        ...
        new_tools.append(tool)
    return {"tools_called": new_tools}  # ← retorna SÓ OS NOVOS
    # operator.add: [5]+[1] = 6 entries corretos

3. Cache com Invalidação

O cache de decisões do LLM (para evitar re-execuções gastando token) agora inclui a AGENT_VERSION no hash. Quando você muda o prompt ou a política, basta bumpar a versão em agent/version.py.

# Em agent/version.py:
AGENT_VERSION = "v2"  # ← bump manual a cada mudança relevante

# Em agent/nodes.py (_cache_key):
def _cache_key(context_text):
    payload = f"{AGENT_VERSION}:{context_text}"
    return hashlib.sha1(payload.encode("utf-8")).hexdigest()

Isso garante que re-execuções do mesmo ticket sempre usem o cache, mas mudanças de comportamento forçam uma nova chamada ao LLM.

4. Nó act com Ações Reais (POST/PATCH)

O nó act agora realmente executa a ação na API industrial. O fluxo é:

  1. interrupt() — pausa o grafo, salva o estado (HITL).
  2. Humano confirma ou cancela (via Streamlit).
  3. Se confirmado, o agente chama o endpoint correto via tractian_request.
  4. Retorna o resultado da API no trace.

Os 4 tipos de ação suportados

TipoEndpointPermissão
reprocessPOST /analyses/{id}/reprocessaction_low
specialistPOST /analyses/{id}/request-specialistaction_low
retrainPOST /models/{id}/request-retrainingaction_high
update_configPATCH /assets/{id}action_high

Como a ação é determinada

A helper _extract_action() analisa o texto do LLM e mapeia por palavras-chave:

"reprocessar" → reprocess
"especialista" → specialist
"retreinamento" → retrain
"config"/"criticidade" → update_config

O action_target (ID do alvo) é extraído dos dados coletados (primeira análise disponível, modelo, ou o próprio ativo).

5. Estrutura do AgentState

O estado do grafo agora inclui campos de ação:

class AgentState(TypedDict):
    # --- Entrada ---
    ticket_id: str
    case_id: str
    company_id: str
    user_id: str
    asset_id: str
    message: str

    # --- Contexto coletado ---
    raw: dict[str, dict]      # envelops brutos por categoria
    quality_verdict: Literal["ok", "partial", "incomplete", "unavailable"] | None
    data_gaps: Annotated[dict, operator.or_]
    next_tool: str | None
    tools_called: Annotated[list[str], operator.add]  # ← appenda

    # --- Decisão ---
    decision: Literal["orient", "act", "escalate"] | None
    decision_justification: str | None
    action_type: Literal["reprocess", "specialist", "retrain", "update_config"] | None
    action_target: str | None

    # --- Resultado ---
    response: str | None
    trace: Annotated[list[dict], operator.add]

Teste seu entendimento

Pergunta 1
O que acontece se o humano cancelar no HITL?
Resposta

O nó act retorna decision="escalate" e decision_justification indica que a ação foi cancelada. O trace registra "cancelled_by_human".

Pergunta 2
Por que o operator.add no tools_called causa duplicatas?
Resposta

operator.add concatena listas. Se o nó investigate retorna a lista inteira (5 tools) em cada passada, e o state já tem 5, o resultado é 5+5=10. Na verdade deveria ser 5+1=6.
